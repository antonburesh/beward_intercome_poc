# Документация: SIP-сервер и браузерный софтфон для Beward

Локальный (и серверный) стек для панели **Beward DKS20211**. Звонок на любую квартиру `1`–`1000` приходит на одну страницу в браузере: ответить, говорить, открыть дверь, записать лицо, временный код и ключ.

Репозиторий: исходники и примеры настроек. Пароли и рабочие адреса в git не хранятся.

---

## 1. Архитектура

```
Панель Beward ──SIP udp/15060──► Kamailio (контейнер sip)
                                      │
                                      │ INVITE → 101
                                      │ (+ X-Apartment, X-Door-Station)
                                      ▼
                               Softphone 101 (контейнер phone)
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
              HTTP страница      RTP звук/видео    HTTP CGI панели
              / и /settings      G.711 + H.264     снимок, дверь,
              API /api-intercom/*  напрямую         лица, коды, ключи
                    │
                    ▼
              Браузер жителя
              (микрофон → WebRTC → Opus → G.711 на панель)
```

| Компонент | Роль |
| --- | --- |
| **Kamailio** | SIP-регистрация панелей и софтфона, перевод квартир `1`–`1000` на `101`. Медиа не пересылает |
| **phone** | Софтфон `101`, HTTP-страница Vue, WebRTC-микрофон, RTP, команды панели |
| **web/** | Исходники страницы; в образ попадает сборка `web/dist` |
| **Панель** | SIP-клиент + веб-CGI Beward |

Сигнализация SIP идёт через Kamailio. После ответа звук и видео идут **напрямую** между панелью и процессом `phone` (RTP). `Record-Route` в SIP — это маршрут сигнализации, не запись разговора.

---

## 2. Как проходит звонок

1. На панели набирают квартиру, например `44`.
2. Панель шлёт `INVITE` на Kamailio: `ADVERTISE_IP`, порт **`15060`**, от своего SIP-пользователя (например `100`).
3. Kamailio проверяет digest, видит номер `1`–`1000` и переводит вызов на софтфон `101`. В заголовки добавляет:
   - `X-Apartment: 44`
   - `X-Door-Station: 100` (SIP-имя панели)
   - в `From` отображаемое имя `Apt-44`
4. Софтфон показывает звонок на странице: квартира, имя панели, JPEG-снимок.
5. **Ответить** — `200 OK` с SDP, RTP звука (G.711) и видео (H.264). Микрофон браузера поднимается через WebRTC.
6. **Открыть дверь** — HTTP CGI только той панели, которая звонит.
7. По желанию софтфон шлёт уведомление на сайт (`notify_host`).

Пока процесс `phone` не запущен или не зарегистрирован, номер `101` на Kamailio пропадает: панель получит отказ, экран не зазвонит. Регистрация софтфона живёт **120 секунд** и обновляется примерно раз в минуту.

Панель сопоставляется по `X-Door-Station`, иначе по пользователю `From`. **IP источника UDP не используется** (за NAT/Docker он часто чужой).

Софтфон принимает только `INVITE` с заголовком `X-Apartment` (его ставит Kamailio). Голый `INVITE` на порт софтфона — сканер, ответ `403`.

---

## 3. Порты

| Порт | Протокол | Куда | Зачем |
| --- | --- | --- | --- |
| `15060` | UDP/TCP | Kamailio | SIP с панелей и софтфона. Не `5060` — автосканеры бьют в стандартный порт |
| `5062` | UDP | phone | SIP софтфона. **В prod снаружи не публикуется** — только сеть Docker (`tango_net`) |
| `40000` | UDP | phone | RTP звука с/на панель |
| `40002` | UDP | phone | RTP видео с панели |
| `40010` | UDP | phone | WebRTC (микрофон браузера) |
| `8090` | TCP | phone (local) | Страница и API, только `127.0.0.1` |
| `8091` | TCP | phone (prod) | То же на сервере, только `127.0.0.1` (снаружи — через nginx) |

## 4. Настройки

### 4.1. Где лежат файлы

| Среда | Каталог | В git |
| --- | --- | --- |
| Примеры | `config.example/` | да |
| Локальный Docker / `python3 phone/app.py` | `config/` в корне репозитория | нет (`.gitignore`) |
| Прод-сервер | `/etc/sip-server/` | нет |

Первый локальный запуск:

```bash
mkdir -p config
cp config.example/env config.example/settings.json config.example/subscriber config/
```

На сервере каталог создаёт `deploy/up.sh`. Вручную:

```bash
sudo mkdir -p /etc/sip-server
sudo cp config.example/env config.example/settings.json config.example/subscriber /etc/sip-server/
sudo chown -R "$USER" /etc/sip-server
```

Дальше правят **рабочую** копию (`config/` или `/etc/sip-server/`), не пример.

| Файл | Читает | Назначение |
| --- | --- | --- |
| `env` | контейнер `sip` | `ADVERTISE_IP` |
| `settings.json` | процесс phone | SIP софтфона, панели, `notify_host` |
| `subscriber` | Kamailio (dbtext) | SIP-логины и пароли |
| `guest_codes.json` | phone | временные коды (создаётся сам) |
| `keys.json` | phone | ключи с экрана (создаётся сам) |

После правки `env` или `subscriber` контейнер Kamailio нужно пересоздать. После правки `settings.json` — перезапустить `phone` (файл читается один раз при старте).

### 4.2. `env`

```bash
# Адрес этого хоста, который Kamailio объявляет панелям в SIP.
# Тот же адрес должен стоять в settings.json → sip.ip
ADVERTISE_IP=192.168.1.10
```

На проде `deploy/up.sh` подставляет публичный IP сервера (сейчас `158.160.176.80`).

### 4.3. `settings.json`

Полный пример:

```json
{
  "sip": {
    "ip": "192.168.1.10",
    "port": 15060,
    "user": "101",
    "password": "phone-password"
  },
  "notify_host": "tango-dom.ru",
  "panels": [
    {
      "name": "Подъезд 1",
      "sip_user": "100",
      "intercom_id": "intercom_1",
      "ip": "192.168.1.20",
      "username": "admin",
      "password": "admin"
    }
  ]
}
```

#### Объект `sip`

| Поле | Обязательно | Пример | Смысл |
| --- | --- | --- | --- |
| `ip` | да | `192.168.1.10` | Публикуемый адрес для Contact/SDP и совпадение с `ADVERTISE_IP` |
| `port` | да | `15060` | Порт Kamailio, куда регистрируется софтфон |
| `user` | да | `101` | SIP-логин софтфона (должен быть в `subscriber`) |
| `password` | да | `phone-password` | Пароль софтфона (тот же, что в `subscriber`) |

#### `notify_host`

Хост сайта без схемы. При входящем звонке софтфон делает GET:

```http
GET https://{notify_host}/api/intercom/call?intercom_id=...&apartment=...&name=...
```

Пример: `"notify_host": "tango-dom.ru"`.  
Пустая строка или отсутствие поля — уведомления не шлются. Ошибка сайта (404 и т.п.) на SIP-звонок не влияет.

#### Элемент `panels[]`

| Поле | Обязательно | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `name` | да | — | Имя на экране звонка («Подъезд 1») |
| `sip_user` | да | — | SIP-логин панели, тот же что в `subscriber` |
| `ip` | да | — | Адрес панели для HTTP CGI (IP или DNS-имя) |
| `intercom_id` | нет | значение `sip_user` | Идентификатор для уведомления сайта |
| `username` | нет | `admin` | Логин веб-интерфейса панели (Digest, не Basic) |
| `password` | нет | `admin` | Пароль веб-интерфейса |
| `snapshot_path` | нет | `/cgi-bin/images_cgi?channel=0` | CGI снимка |
| `door_path` | нет | `/cgi-bin/intercom_cgi?action=maindoor` | CGI открытия двери |

Телефон к панели ходит с Digest: сначала запрос без пароля, на `401` собирает ответ из `WWW-Authenticate`.

Пример двух панелей:

```json
"panels": [
  {
    "name": "Подъезд 1",
    "sip_user": "100",
    "intercom_id": "intercom_1",
    "ip": "192.168.1.20",
    "username": "admin",
    "password": "секрет-панели-1"
  },
  {
    "name": "Подъезд 2",
    "sip_user": "102",
    "intercom_id": "intercom_2",
    "ip": "192.168.1.21",
    "username": "admin",
    "password": "секрет-панели-2"
  }
]
```

Для второй панели нужна ещё строка в `subscriber` с тем же `sip_user` и паролем SIP (это **другой** пароль, чем веб-логин).

### 4.4. `subscriber` (Kamailio dbtext)

Формат: первая строка — заголовок колонок (не удалять). Далее:

```text
id:логин:домен:пароль:::
```

Пример:

```text
id(int,auto) username(string) domain(string) password(string) ha1(string,null) ha1b(string,null) 
1:100:192.168.1.10:panel-password::
2:101:192.168.1.10:phone-password::
```

| Колонка | Смысл |
| --- | --- |
| `id` | Уникальный номер строки |
| `username` | SIP-логин (`100` — панель, `101` — софтфон) |
| `domain` | Тот же адрес, что `ADVERTISE_IP` / `sip.ip`. При проверке пароля домен не используется (`use_domain=0`) |
| `password` | Пароль SIP в открытом виде; Kamailio считает HA1 сам (`calculate_ha1=yes`) |

Логины не повторяются. Пароль `101` в `subscriber` = `sip.password` в `settings.json`. Пароль `100` настраивается на панели как пароль SIP-аккаунта.

### 4.5. Переменные окружения контейнера `phone`

Задаются в `compose.yaml` / `compose.prod.yaml`.

| Переменная | Пример | Смысл |
| --- | --- | --- |
| `HTTP_HOST` | `0.0.0.0` | На каком адресе слушать HTTP |
| `HTTP_PORT` | `8090` / `8091` | Порт страницы и API |
| `SIP_BIND` | `0.0.0.0` | Bind UDP сокета SIP софтфона |
| `SIP_PORT` | `5062` | Порт SIP софтфона |
| `SIP_REGISTER_HOST` | `sip` | Куда слать REGISTER (имя контейнера Kamailio в Docker) |
| `SIP_CONTACT_HOST` | `phone` | Host в Contact (имя контейнера phone; только prod) |
| `RTP_PORT` | `40000` | UDP звука |
| `VIDEO_PORT` | `40002` | UDP видео |
| `WEBRTC_PORT` | `40010` | UDP WebRTC |

Без `SIP_CONTACT_HOST` в Contact подставляется `sip.ip`. На проде Contact = `phone:5062`, чтобы Kamailio ходил по Docker-сети и **не нужно было публиковать 5062 в интернет**.

## 5. Настройка панели Beward

На панели (веб-интерфейс / SIP):

| Параметр | Значение |
| --- | --- |
| SIP-сервер | `ADVERTISE_IP` (например `158.160.176.80`) |
| Порт SIP | **`15060`** (не 5060) |
| Пользователь | как `sip_user` в `panels` и `subscriber` (например `100`) |
| Пароль | как в строке панели в `subscriber` |
| Квартиры | уже заведены `1`–`1000`; страница их не создаёт |

После смены порта или пароля панель должна успешно сделать REGISTER. В логах Kamailio:

```text
REGISTER ok user=100 src=...
```

## 6. Страница в браузере

### Локально

[http://127.0.0.1:8090](http://127.0.0.1:8090) — только с этой машины.

### Прод

Обычно [https://intercom.tango-dom.ru](https://intercom.tango-dom.ru). Nginx проксирует на `127.0.0.1:8091`.

Маршруты Vue:

| Путь | Экран |
| --- | --- |
| `/` | Входящий вызов |
| `/settings` | Лицо, временный код, ключ |

Кнопки звонка:

| Кнопка | Действие |
| --- | --- |
| Ответить | Снимает трубку, видео, звук, микрофон |
| Отклонить | Отклоняет входящий |
| Завершить | Кладет трубку в разговоре |
| Открыть дверь | CGI основного замка звонящей панели |

Пока звонок только звонит — JPEG с `/snapshot`. После ответа — живое H.264 через WebCodecs. Браузер спросит микрофон; без разрешения панель вас не услышит.

Состояние звонка страница получает по **SSE** `GET /api-intercom/events` (сервер сам пушит изменения). Лица, коды и ключи грузятся только на экране настроек.

## 7. HTTP API

Префикс JSON/управления: **`/api-intercom/`**.  
Медиа и снимки: `/media`, `/snapshot`, `/face` (без префикса).

### Звонок и регистрация

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api-intercom/events` | SSE: поток состояния звонка и регистрации |
| `GET` | `/api-intercom/state` | Разовый снимок того же состояния (для отладки) |
| `POST` | `/api-intercom/answer` | Ответить |
| `POST` | `/api-intercom/reject` | Отклонить входящий |
| `POST` | `/api-intercom/hangup` | Завершить разговор |
| `POST` | `/api-intercom/open` | Открыть дверь |
| `POST` | `/api-intercom/webrtc` | SDP offer микрофона → SDP answer (`Content-Type: application/sdp`) |

Пример состояния:

```bash
curl -s http://127.0.0.1:8091/api-intercom/state
```

```json
{
  "registered": true,
  "error": "",
  "user": "101",
  "server": "158.160.176.80:15060",
  "call": {
    "id": "...",
    "state": "ringing",
    "apartment": "181",
    "panel": "Подъезд 1",
    "panel_known": true,
    "from": "...",
    "to": "...",
    "params": [],
    "headers": [],
    "rtp": 0
  }
}
```

`registered: true` — софтфон на Kamailio.  
`call: null` — нет активного вызова.  
`panel_known: false` — SIP-имя панели нет в `panels` (кнопка двери не сработает).

### Настройки (книга и лица)

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api-intercom/book` | Гости, ключи, список панелей (без логинов) |
| `GET` | `/api-intercom/faces` | Список лиц с панелей (ходит на CGI, может быть долгим) |
| `POST` | `/api-intercom/guest` | Выдать или снять код |
| `POST` | `/api-intercom/guest/clear` | Снять все коды |
| `POST` | `/api-intercom/face` | Загрузить фото (`multipart`: `apartment`, `photo`) |
| `POST` | `/api-intercom/face/delete` | Удалить одно или все лица |
| `POST` | `/api-intercom/key` | Добавить или удалить ключ |
| `POST` | `/api-intercom/key/clear` | Удалить все ключи с экрана |

Примеры:

```bash
# Временный код на 30 минут на все панели
curl -s -X POST http://127.0.0.1:8091/api-intercom/guest \
  -H 'Content-Type: application/json' \
  -d '{"apartment":"12","minutes":30,"all":true}'

# Код только на одну панель
curl -s -X POST http://127.0.0.1:8091/api-intercom/guest \
  -H 'Content-Type: application/json' \
  -d '{"apartment":"12","minutes":60,"panel":"192.168.1.20"}'

# Снять код квартиры
curl -s -X POST http://127.0.0.1:8091/api-intercom/guest \
  -H 'Content-Type: application/json' \
  -d '{"apartment":"12","remove":true}'

# Ключ Mifare
curl -s -X POST http://127.0.0.1:8091/api-intercom/key \
  -H 'Content-Type: application/json' \
  -d '{"apartment":"12","key":"A1B2C3D4"}'
```

### Медиа

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/media` | Поток PCM/видео в браузер (длинное соединение) |
| `GET` | `/snapshot` | JPEG с камеры текущей звонящей панели |
| `GET` | `/face?panel=IP&id=ID` | Миниатюра лица с панели |

## 8. Звук и видео

- **Входящий звук панели → браузер:** RTP G.711 → PCM → эхоподавитель → поток `/media` → Web Audio.
- **Микрофон браузера → панель:** `getUserMedia` → WebRTC (Opus) → Python (`aiortc`) → PCM 8 кГц → G.711 RTP. В SDP ответа сервера подставляется публичный адрес; STUN Google не используется.
- **Видео:** до ответа — JPEG; после — H.264 RTP → WebCodecs на canvas.
- Исходящий на панель кодек по умолчанию **G.711A** (PCMA). G.711U на этой панели динамик может молчать; если панель шлёт μ-law, исходящий звук подстраивается.

## 9. Функции настроек

### Вход по лицу

Житель указывает квартиру и фото. Телефон жмёт JPG (не меньше 300 px по стороне, не больше 100 КБ) и пишет на **все** панели из `panels`. Имя и номер документа на панели = номер квартиры. Квартира на панели должна уже существовать.

### Временный код

- 5 цифр, `10000`–`99999`.
- На квартиру один действующий код.
- Срок на экране: 15 / 30 / 60 / 180 минут (сервис: от 5 минут до суток).
- Можно «на все домофоны» или на один `ip`.
- Прежний код панели запоминается и возвращается по истечении срока или при удалении.
- Состояние в `guest_codes.json` переживает перезапуск.

### Ключ

UID Mifare: 8 или 14 hex-символов (пробелы/`:`/`-` допустимы). Пишется на все панели, где есть квартира. Список на экране — только ключи, добавленные отсюда (`keys.json`). NFC телефона обычно не подходит.

## 10. Защита SIP

| Мера | Что делает |
| --- | --- |
| Порт `15060` вместо `5060` | Автосканеры стандартного порта вас не находят |
| Молчаливый отказ неизвестному логину | Нет `401` с nonce → нет подтверждения «здесь SIP» |
| Модуль `pike` | Частые запросы с одного IP отбрасываются без ответа (~30 за 2 с) |
| `5062` не опубликован в prod | Сканер не шлёт `INVITE` напрямую на софтфон |
| `X-Apartment` обязателен | Софтфон отвергает голый `INVITE` (`403`) |
| Digest в `subscriber` | Без пароля регистрация и вызов не проходят |

Рекомендуется также сменить веб-пароль панели с `admin`/`admin` и держать длинные SIP-пароли в `subscriber`.

## 11. Запуск

### Локально (Docker)

```bash
mkdir -p config
cp config.example/env config.example/settings.json config.example/subscriber config/
# Отредактировать ADVERTISE_IP, sip.ip, пароли, ip панели

docker compose up -d --build
```

Страница: [http://127.0.0.1:8090](http://127.0.0.1:8090).

Остановка:

```bash
docker compose stop
```

Логи:

```bash
docker logs sip --tail 50
docker logs phone --tail 50
```

### Прод (`compose.prod.yaml`)

- Сеть Docker: внешняя `tango_net`.
- Конфиг: `/etc/sip-server/`.
- Страница на хосте: `127.0.0.1:8091` (nginx снаружи).
- Деплой **только через GitHub Actions** (push в `master` или `workflow_dispatch`).

Секрет репозитория: `SSH_PRIVATE_KEY` — ключ к `admin@158.160.176.80`. Джоба копирует дерево в `~/sip-server` и запускает `deploy/up.sh` (подставляет IP, порт `15060`, `docker compose -f compose.prod.yaml up -d --build`).

```bash
cd web && npm ci && npm run build
```

## 12. Несколько панелей

Сейчас в примере одна панель (`100`) и один софтфон (`101`). Панелей может быть сколько угодно: каждый домофон — свой SIP-логин и своя запись в `panels`. Все они звонят на **один и тот же** софтфон `101` и одну страницу.

### Что куда пишется

| Действие | Куда уходит |
| --- | --- |
| Входящий звонок | На `101`, на экране имя звонящей панели |
| Открыть дверь | Только панель текущего звонка |
| Фото лица | На **все** панели из `panels` |
| Ключ | На **все** панели из `panels`, где есть эта квартира |
| Временный код | На все или на одну — как выбрано в «Куда записать код» |

Квартиры на каждой панели заводят заранее. Страница квартиру не создаёт: если её нет хотя бы на одной выбранной панели, код/фото/ключ туда не запишутся.

### Пошагово: добавить ещё одну панель

Допустим, уже есть «Подъезд 1» (`100`), добавляем «Подъезд 2» с логином `102`.

**1. SIP-учётка в `subscriber`**

Локально — `config/subscriber`, на сервере — `/etc/sip-server/subscriber`. Новый `id` и уникальный логин; домен = `ADVERTISE_IP` / `sip.ip`:

```text
id(int,auto) username(string) domain(string) password(string) ha1(string,null) ha1b(string,null) 
1:100:158.160.176.80:panel-password-1::
2:101:158.160.176.80:phone-password::
3:102:158.160.176.80:panel-password-2::
```

**2. Запись в `settings.json` → `panels`**

```json
"panels": [
  {
    "name": "Подъезд 1",
    "sip_user": "100",
    "intercom_id": "intercom_1",
    "ip": "192.168.1.20",
    "username": "admin",
    "password": "web-password-1"
  },
  {
    "name": "Подъезд 2",
    "sip_user": "102",
    "intercom_id": "intercom_2",
    "ip": "192.168.1.21",
    "username": "admin",
    "password": "web-password-2"
  }
]
```

`sip_user` должен совпадать с логином в `subscriber`.  
`ip` — адрес панели для CGI (снимок, дверь, лица, коды, ключи); это не обязан быть тот же адрес, с которого приходит SIP (за NAT часто другой).  
`username` / `password` — вход в **веб** панели (Digest), не SIP-пароль.

**3. Настройка на самой панели Beward**

| Параметр | Значение |
| --- | --- |
| SIP-сервер | тот же `ADVERTISE_IP`, что у первой панели |
| Порт | `15060` |
| Пользователь | `102` |
| Пароль | `panel-password-2` из `subscriber` |

Квартиры `1`–`1000` на панели уже должны быть заведены.

**4. Перезапуск**

После правки `subscriber` пересоздают Kamailio (читает файл при старте). После правки `settings.json` перезапускают `phone`.

```bash
# локально
docker compose up -d --force-recreate sip
docker compose restart phone

# прод (после правок в /etc/sip-server/)
cd ~/sip-server && docker compose -f compose.prod.yaml up -d --force-recreate sip
docker compose -f compose.prod.yaml restart phone
```

На проде конфиг правится на сервере в `/etc/sip-server/`; деплой из git сам пароли панелей не меняет (каталог `config` в rsync не копируется, том — `/etc/sip-server`).

**5. Проверка**

```bash
docker logs sip --tail 30 | grep REGISTER
```

Ожидается:

```text
REGISTER ok user=100 ...
REGISTER ok user=102 ...
REGISTER ok user=101 ...
```

Звонок с подъезда 2 должен показать на экране «Подъезд 2». В отладке — `X-Door-Station: 102`. Снимок и «Открыть дверь» ходят на `ip` этой панели.

### Типичные ошибки

| Симптом | Причина |
| --- | --- |
| Звонок есть, панель «неизвестна», дверь не открывается | `sip_user` в `panels` не совпадает с SIP-логином панели / нет записи в `panels` |
| Нет снимка / лиц / кодов на новой панели | Неверный `ip` или веб-логин/пароль; с сервера панель по HTTP не отвечает |
| `REGISTER rejected` для нового логина | Нет строки в `subscriber` или неверный пароль; контейнер `sip` не пересоздали |
| Код записался не на ту панель | В форме выбран один домофон; для всех нужен пункт «На все домофоны» |

## 13. Софтфоны

### Как устроен софтфон в этом проекте

«Софтфон» здесь — процесс `phone` (Python) + страница в браузере. Он:

1. Регистрируется на Kamailio как SIP-пользователь **`101`** (логин и пароль из `settings.json` → `sip` и из `subscriber`).
2. Принимает все вызовы квартир `1`–`1000`: Kamailio в `kamailio.cfg` всегда переписывает такие `INVITE` на `sip:101@...`.
3. Отдаёт одну веб-страницу: один экран ожидания / один активный разговор.

В `subscriber` софтфон — обычная строка рядом с панелями:

```text
2:101:158.160.176.80:phone-password::
```

В `settings.json`:

```json
"sip": {
  "ip": "158.160.176.80",
  "port": 15060,
  "user": "101",
  "password": "phone-password"
}
```

Пароль в обоих местах должен совпадать. Порт `15060` — порт **Kamailio**, куда софтфон шлёт REGISTER, а не порт самого софтфона (`5062` внутри Docker).

### Один софтфон на все панели

Модель проекта:

- Панелей много (`100`, `102`, …).
- Софтфон **один** (`101`).
- Страница **одна**.

Любой подъезд звонит на ту же вкладку. Одновременно обрабатывается **один** вызов: пока идёт `ringing` или `talking`, второй `INVITE` получит `486 Busy Here`.

Несколько вкладок браузера на одну страницу можно открыть — состояние общее с сервера (SSE), но микрофон/медиа лучше держать в одной вкладке.

### Что не поддерживается «из коробки»

| Идея | Сейчас |
| --- | --- |
| Второй софтфон `102` для части квартир | Нет: в Kamailio квартира всегда уходит на `101` |
| Отдельная страница на каждый подъезд | Нет: один процесс `phone`, один UI |
| Несколько контейнеров `phone` с разными SIP-логинами | Не предусмотрено: один Contact `101`, общие порты RTP/WebRTC |
| Классический софтфон (Linphone, Zoiper) вместо страницы | Технически можно зарегистрировать другой клиент как `101`, но тогда не будет веб-API, лиц, кодов и двери с этой страницы; текущий процесс `phone` при этом не должен занимать тот же логин |

Чтобы завести второй независимый «телефон» (другая страница / другой набор квартир), нужны отдельные правки Kamailio (другой номер назначения), второй процесс софтфона и разведение портов — этого в репозитории пока нет.

### Регистрация и жизнь софтфона

| Параметр | Значение |
| --- | --- |
| Логин | `sip.user` (обычно `101`) |
| Expires | 120 с, обновление примерно раз в минуту |
| Contact в prod | `sip:101@phone:5062` (`SIP_CONTACT_HOST=phone`) |
| Медиа (SDP) | адрес `sip.ip`, порты `40000` / `40002` |

Пока контейнер `phone` выключен или `registered: false`, панели до `101` не дозвонятся.

Проверка:

```bash
curl -s http://127.0.0.1:8091/api-intercom/state
# "registered": true, "user": "101", "server": "...:15060"
```

```bash
docker logs sip --tail 20 | grep 'REGISTER ok user=101'
```

### Смена логина или пароля софтфона

Если меняете `101` на другой номер (например `201`):

1. Строка в `subscriber` с новым логином и паролем.
2. `sip.user` / `sip.password` в `settings.json`.
3. В `kamailio/kamailio.cfg` заменить жёстко прошитый `101` в маршруте квартир на новый номер (и задеплоить).
4. Пересоздать `sip`, перезапустить `phone`.

Без правки `kamailio.cfg` квартиры по-прежнему уйдут на `101`, даже если софтфон зарегистрирован как `201`.

## 15. Ограничения

- Один софтфон `101`: все квартиры `1`–`1000` и все панели на одну страницу (см. §13).
- Одновременно один разговор; второй вызов получит занято.
- На панель уходит только звук микрофона, без видео с компьютера.
- Локальная страница слушает только `127.0.0.1`.
- Временный код действует весь срок, не «один проход» (панель не шлёт событие использования).
- На квартиру один гостевой код.
- Список ключей — только добавленные с этой страницы.
- NFC телефона обычно не заменяет Mifare.
- После правки `web/` нужна пересборка образа или `npm run build`.

## 16. Быстрая диагностика

| Симптом | Что проверить |
| --- | --- |
| Экран не звонит | `registered` в `/api-intercom/state`; логи `sip` — есть ли `REGISTER ok user=101` |
| Панель не регистрируется | Порт на панели **15060**; логин/пароль = `subscriber`; `REGISTER ok user=…` |
| Новая панель звонит, но «неизвестна» | `sip_user` в `panels` = SIP-логин панели; перезапущен ли `phone` после правки `settings.json` |
| Второй софтфон / другая страница | Не поддерживается без правок Kamailio и второго процесса — см. §13 |
| «Странные» квартиры / From `666` | Старый открытый `5062` или протухший деплой; после фикса — только вызовы с `X-Apartment` |
| Нет снимка / дверь молчит | `panels[].ip`, `username`/`password`, доступность CGI с сервера |
| Нет микрофона | Разрешение браузера; `POST /api-intercom/webrtc`; UDP `40010` с клиента до сервера |
| Сайт «не принял звонок» | `notify_host` и наличие `GET /api/intercom/call` на сайте; на SIP не влияет |
