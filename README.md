# Домофон Beward и локальный SIP

Локальная схема, чтобы вызов с панели Beward на любую квартиру с 1 по 1000 приходил на одну страницу в браузере: с номером квартиры, картинкой, звуком в обе стороны и кнопкой открытия двери.

Сеть: `192.168.9.0/24`. Панель `192.168.9.82`. Компьютер с этой страницей `192.168.9.106`.

## Как проходит звонок

1. На панели набирается квартира, например 44.
2. Панель отправляет SIP-вызов на Kamailio (`192.168.9.106:5060`) от имени пользователя `100`.
3. Kamailio принимает номера `1`–`1000` и переводит их на софтфон `101`. Номер квартиры остаётся в заголовке `X-Apartment` и в имени `From` (`Apt-44`). Панель остаётся в заголовке `X-Door-Station` (SIP-имя панели, не её IP).
4. Страница [http://127.0.0.1:8090](http://127.0.0.1:8090) показывает входящий вызов.
5. После **Ответить** звук и видео идут напрямую между панелью и компьютером. Kamailio звук и видео не пересылает.
6. Микрофон компьютера уходит обратно на панель. **Открыть дверь** шлёт панели команду открыть основной замок.

## Страница софтфона

Адрес: [http://127.0.0.1:8090](http://127.0.0.1:8090)

Кнопки появляются во время звонка:

| Кнопка | Что делает |
| --- | --- |
| Ответить | Снимает трубку, включает картинку, звук панели и микрофон |
| Отклонить | Отклоняет входящий вызов |
| Завершить | Кладёт трубку во время разговора |
| Открыть дверь | Открывает основной замок панели |

При ответе браузер спросит доступ к микрофону. Его нужно разрешить, иначе панель вас не услышит. Если панель слышит сама себя, убавьте громкость динамиков или наденьте наушники.

Картинка — это H.264 с панели. Если она погасла и появилась снова, декодер в браузере восстановился со следующего ключевого кадра.

## Запуск

Из каталога проекта:

```bash
docker compose up -d
python3 phone/app.py
```

Первая команда поднимает SIP-сервер (контейнер `sip`). Вторая — софтфон. Пока процесс `python3 phone/app.py` не запущен, номер `101` не зарегистрирован и звонок некуда доставить.

Остановить SIP-сервер:

```bash
docker compose stop
```

Логи сигнализации:

```bash
docker logs sip --tail 50
```

Состояние софтфона: [http://127.0.0.1:8090/api/state](http://127.0.0.1:8090/api/state). Поле `registered` должно быть `true`.

## Учётные записи SIP

Файл `kamailio/dbtext/subscriber`. Домен в таблице — `192.168.9.106`, при проверке пароля он не используется.

| Номер | Пароль | Кто |
| --- | --- | --- |
| 100 | `beward100` | Панель |
| 101 | `phone101` | Страница софтфона |

На панели в SIP указано:

- сервер и прокси: `192.168.9.106`, порт `5060`
- пользователь: `100`
- пароль: `beward100`

Квартиры `1`–`1000` на панели заполнены номером вызова, равным номеру квартиры. Звонок на такой номер Kamailio отдаёт софтфону `101`.

## Открытие двери

Кнопка на странице вызывает у панели

`http://192.168.9.82/cgi-bin/intercom_cgi?action=maindoor`

с заводским входом веб-интерфейса `admin` / `admin`. Команда уходит только после нажатия кнопки и только на панель текущего звонка. Настройки панели при этом не меняются.

Список панелей и логин софтфона лежат в `phone/settings.json`. Если SIP-имени панели нет в списке, звонок всё равно виден, а команда двери не отправляется.

## Файлы

| Файл | Зачем |
| --- | --- |
| `compose.yaml` | Контейнер Kamailio, порты `5060/udp` и `5060/tcp` |
| `.env` | `ADVERTISE_IP` — адрес компьютера, который видит панель |
| `kamailio/kamailio.cfg` | Регистрация и перевод квартир `1`–`1000` на `101` |
| `kamailio/dbtext/subscriber` | Логины `100` и `101` |
| `phone/settings.json` | Адрес SIP-сервера, логин софтфона `101` и список панелей |
| `phone/app.py` | Запуск софтфона (`python3 phone/app.py`). Страница, SIP, картинка и дверь — в соседних файлах пакета `phone` |

Образ: `ghcr.io/kamailio/kamailio-ci:6.1-alpine`. На macOS Docker не даёт настоящего host-network, поэтому в логах Kamailio источник панели часто выглядит как `192.168.65.1`. Для звонка с панели на софтфон это нормально: ответ и медиа идут на `192.168.9.106`.

## Ограничения

- Софтфон один: все квартиры `1`–`1000` звонят на страницу `101`.
- Обратно на панель уходит только звук микрофона, без видео с компьютера.
- Страница слушает только `127.0.0.1:8090`, с другого устройства в сети её не открыть.
- Если софтфон перезапустили, страницу нужно обновить и снова разрешить микрофон при ответе.
