# Домофон Beward и локальный SIP

Локальная схема для панели Beward DKS20211. Вызов на любую квартиру с 1 по 1000 приходит на одну страницу в браузере. Со страницы можно ответить, говорить, открыть дверь текущего звонка, а также записать фото для входа по лицу, временный код и ключ.

Адреса и пароли этого стенда лежат только в каталоге `config/`. В git его нет. Страница: [http://127.0.0.1:8090](http://127.0.0.1:8090).

Страница слушает только localhost. С телефона в той же Wi-Fi её не открыть, пока процесс запущен на этом компьютере.

## Как проходит звонок

1. На панели набирают квартиру, например 44.
2. Панель шлёт SIP-вызов на Kamailio (адрес из `config/env`, порт `5060`) от своего SIP-пользователя.
3. Kamailio принимает номера `1`–`1000` и переводит их на софтфон `101`. Номер квартиры остаётся в заголовке `X-Apartment` и в имени `From` (`Apt-44`). Какая панель звонит, записано в `X-Door-Station` (её SIP-имя, не IP).
4. Страница показывает входящий вызов: номер квартиры, имя панели и снимок камеры.
5. После **Ответить** звук и видео идут напрямую между панелью и компьютером. Kamailio медиа не пересылает. `Record-Route` в SIP — это не запись разговора.
6. **Открыть дверь** открывает основной замок только той панели, которая сейчас звонит.

На macOS Docker не даёт настоящего host-network. В логах Kamailio источник пакета часто `192.168.65.1`. Это адрес моста Docker, а не адрес панели. Панель узнаётся по `X-Door-Station`, а если заголовка нет — по пользователю `From`.

Регистрация софтфона живёт 120 секунд и обновляется примерно раз в минуту. Пока процесс `python3 phone/app.py` не запущен, номер `101` на сервере пропадает и новый звонок некуда доставить: панель получит отказ, а экран не зазвонит.

## Звук и картинка

Звук и видео — разные RTP-сессии, они идут одновременно.

Ответ софтфона по звуку — только G.711A, 8 кГц, пакеты по 20 мс. Если ответить G.711U, динамик этой панели молчит. Если панель всё же присылает G.711U, исходящий звук переключается на тот же кодек. Первый пакет помечается marker-битом. Куда слать RTP, софтфон узнаёт по адресу, с которого панель сама прислала звук.

Микрофон браузера идёт так: `getUserMedia` (эхоподавление, шумоподавление и автоуровень включены) → WebRTC до процесса Python → Opus → PCM 8 кГц → G.711 на панель. Сигнализация WebRTC — один `POST /api/webrtc` с SDP, дальше медиа локальное. Свой голос в трубку телефона не подмешивается. То, что панель возвращает обратно (её микрофон слышит динамик), вычитается эхоподавителем в `phone/echo.py`, прежде чем попасть в динамики браузера.

Пока вызов только звонит, картинка — JPEG-снимок. После ответа идёт живое видео H.264 через WebCodecs. Если картинка погасла, она вернётся со следующего ключевого кадра.

При ответе браузер спросит доступ к микрофону. Без разрешения панель вас не услышит. После перезапуска софтфона страницу нужно обновить и при следующем ответе снова разрешить микрофон.

## Страница

Адрес: [http://127.0.0.1:8090](http://127.0.0.1:8090)

«Вызов» — входящий звонок. «Настройки» — карточки «Вход по лицу», «Временный код» и «Ключ». Они стоят в один ряд, если ширина позволяет. Если карточка не помещается, она переносится на следующую строку и остаётся по центру. На узком экране они идут друг под другом. Кнопки звонка ведут себя так же. Новый звонок сам открывает «Вызов».

Во время звонка:

| Кнопка | Что делает |
| --- | --- |
| Ответить | Снимает трубку, включает видео, звук панели и микрофон |
| Отклонить | Отклоняет входящий вызов |
| Завершить | Кладёт трубку во время разговора |
| Открыть дверь | Открывает основной замок панели, которая звонит |

Под звонком есть блок отладки: квартира, панель, состояние SIP и заголовки. Это не настройки жителя.

Состояние: [http://127.0.0.1:8090/api/state](http://127.0.0.1:8090/api/state). Поле `registered` должно быть `true`.

### Вход по лицу

Житель указывает квартиру и фотографию. Телефон сам уменьшает снимок: панели нужен JPG не меньше 300 пикселей по каждой стороне и не больше 100 КБ. Фото пишется на каждую панель из `config/settings.json` в белый список, имя и номер документа равны номеру квартиры.

В списке у каждой записи есть миниатюра с панели. **Удалить фото** стирает эту запись. **Удалить все фотографии** стирает все лица, которые панель отдала в списке, на всех настроенных домофонах. Квартиры при этом не создаются.

### Временный код

У квартиры на панели одно поле кода двери: 5 цифр, от 10000 до 99999. Гость набирает код и нажимает кнопку вызова. Панель не сообщает, что код уже использовали, поэтому код действует всё выбранное время, а не один проход.

На одну квартиру — один действующий код. Пока он не снят, второй для той же квартиры не выдаётся. Разные квартиры могут иметь коды одновременно.

В поле «Куда записать код» по умолчанию «На все домофоны»: один и тот же код пишется на каждую панель. Можно выбрать один домофон, тогда остальные не меняются и позже этот код сами не получат. Срок на экране: 15 минут, 30 минут, час или 3 часа. Сервис принимает от 5 минут до суток.

Сервис запоминает прежний код каждой панели и возвращает его, когда срок выходит или житель нажимает **Удалить код**. Если на панели код уже заменили руками, чужое значение не затирается. Если панель молчит в момент удаления, код остаётся в списке и снятие повторяется. Если панель молчала при выдаче, код дописывается, когда она снова отвечает. Перезапуск телефона срок не сбрасывает: незакрытые коды лежат в `config/guest_codes.json` и снимаются по времени.

Квартира, которой на панели нет, не создаётся. Если её нет хотя бы на одной выбранной панели, код никуда не пишется.

### Ключ

Житель вписывает номер квартиры и номер ключа, который уже известен. Это UID метки Mifare: 8 или 14 шестнадцатеричных знаков. Пробелы, двоеточия и дефисы можно оставить, они убираются. Пластиковая карта и наклейка подходят, потому что у них постоянный UID. NFC телефона панель как Mifare-ключ обычно не принимает.

Ключ сразу пишется на все панели из настроек, где эта квартира уже есть. Выбора «только этот домофон» нет. Квартира не создаётся. Если панель не ответила, ключ остаётся на тех, что ответили, и на экране будет имя той, что не записалась.

Список показывает только ключи, добавленные с этого экрана (`phone/keys.json`). **Удалить** и **Удалить все ключи** снимают только их и тоже со всех панелей. Ключи, заведённые на панели мимо этой страницы, список не трогает.

## Настройки

В git хранятся только примеры в `config.example/`. На сервере рабочие файлы лежат в `/etc/sip-server/`. Kamailio и софтфон читают этот каталог. В образ и в коммиты пароли не попадают. Локальный запуск без prod-compose по-прежнему использует каталог `config/` в репозитории.

Первый запуск на сервере создаёт `/etc/sip-server` сам (`deploy/up.sh`). Вручную:

```bash
sudo mkdir -p /etc/sip-server
sudo cp config.example/env config.example/settings.json config.example/subscriber /etc/sip-server/
sudo chown -R "$USER" /etc/sip-server
```

Дальше правится уже `/etc/sip-server/`, не пример.

| Файл | Куда попадает | Что задаёт |
| --- | --- | --- |
| `/etc/sip-server/env` | переменная контейнера `sip` | `ADVERTISE_IP` — адрес этого компьютера, который Kamailio объявляет панелям |
| `/etc/sip-server/settings.json` | процесс `python3 phone/app.py` | куда софтфон регистрируется, его логин и список панелей |
| `/etc/sip-server/subscriber` | том `/etc/kamailio/dbtext/subscriber` | SIP-логины панелей и софтфона |
| `/etc/sip-server/guest_codes.json` | тот же процесс | выданные временные коды и прежние коды квартир. Файл появляется сам |
| `/etc/sip-server/keys.json` | тот же процесс | номера ключей, введённые на странице. Файл появляется сам |

`sip.ip` в `settings.json` и `ADVERTISE_IP` в `env` — один и тот же адрес. Софтфон слушает UDP на нём. Если адреса нет на компьютере, процесс не запустится. Домен в каждой строке `subscriber` — тоже этот адрес. При проверке пароля домен не используется.

Поля панели в `settings.json`:

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `name` | да | имя на экране звонка |
| `sip_user` | да | SIP-пользователь этой панели, тот же номер, что в `subscriber` |
| `ip` | да | адрес панели в сети |
| `username`, `password` | нет | вход в веб-интерфейс. Если не указаны, `admin` / `admin` |
| `snapshot_path` | нет | снимок. По умолчанию `/cgi-bin/images_cgi?channel=0` |
| `door_path` | нет | замок. По умолчанию `/cgi-bin/intercom_cgi?action=maindoor` |

Строка `subscriber` — это `id:логин:домен:пароль:::`. Первая строка файла — заголовок колонок, её не удаляют. Номера логинов не повторяются.

После правки `/etc/sip-server/env` или `/etc/sip-server/subscriber` контейнер нужно пересоздать: он читает их при старте.

```bash
docker compose up -d --force-recreate
```

После правки `/etc/sip-server/settings.json` перезапускают софтфон: файл читается один раз.

```bash
python3 phone/app.py
```

### Ещё одна панель

1. В `/etc/sip-server/subscriber` добавьте строку со своим номером и паролем, домен как у остальных.
2. В `/etc/sip-server/settings.json` в массив `panels` добавьте объект `name`, `sip_user`, `ip`.
3. На самой панели укажите SIP-сервер `ADVERTISE_IP`, порт `5060`, этого пользователя и этот пароль.
4. Пересоздайте контейнер и перезапустите софтфон, как выше.

Квартиры на новой панели уже должны быть заведены. Страница их не создаёт.

Звонок сопоставляется с панелью по `X-Door-Station`, иначе по пользователю `From`. IP отправителя UDP не используется.

Фото и ключ пишутся на все панели из `panels`. Временный код — на все или на одну, как выбрано на экране. Открытие двери во время звонка — только на звонящую панель. Если SIP-имени панели нет в списке, звонок всё равно виден, а кнопка двери не срабатывает.

## Запуск

Из каталога проекта:

```bash
docker compose up -d --build
```

Команда поднимает два контейнера. `sip` — Kamailio, порты `5060/udp` и `5060/tcp`, настройки из `config/env` и `config/subscriber`. `phone` — софтфон: страница на [http://127.0.0.1:8090](http://127.0.0.1:8090), SIP и RTP опубликованы на адресе из `sip.ip`, чтобы панель до них дошла. Внутри контейнера этого адреса нет, поэтому сокеты слушают `0.0.0.0`, а в SIP и SDP подставляется `sip.ip`. Если каталога `config/` ещё нет, сначала скопируйте туда примеры, как в разделе «Настройки».

Фото для входа по лицу уменьшает Pillow внутри образа. На macOS без контейнера ту же работу делает `/usr/bin/sips`.

Остановить оба контейнера:

```bash
docker compose stop
```

Логи сигнализации:

```bash
docker logs sip --tail 50
```

Проверки без панели:

```bash
python3 -m unittest tests.test_guest tests.test_keys tests.test_echo tests.test_outgoing_audio tests.test_webrtc_mic
```

## Учётные записи SIP

Логины и пароли задаются в `/etc/sip-server/subscriber` и в `sip` внутри `/etc/sip-server/settings.json`. В репозитории их нет. На панели сервер SIP — это `ADVERTISE_IP`, порт `5060`, пользователь и пароль — строка этой панели в `subscriber`.

Квартиры `1`–`1000` на панели уже заведены, номер вызова равен номеру квартиры. Заново их создавать не нужно: код, фото и ключ только дополняют существующую квартиру.

## Открытие двери

Кнопка вызывает у панели текущего звонка

`/cgi-bin/intercom_cgi?action=maindoor`

Вход — из настроек панели, по умолчанию `admin` / `admin`. Команда уходит только после нажатия и только на эту панель. Громкость, SIP и остальные настройки панели страница не меняет.

| `phone/door.py` | Снимок, замок, лица, квартиры, ключи |

Образ: `ghcr.io/kamailio/kamailio-ci:6.1-alpine`.

## Ограничения

- Софтфон один: все квартиры `1`–`1000` звонят на страницу `101`.
- На панель уходит только звук микрофона, без видео с компьютера.
- Страница доступна только с этого компьютера, `127.0.0.1:8090`.
- Временный код действует весь срок, а не ровно один проход: панель не присылает событие «код использован».
- На квартиру один код. Второй заменил бы первый, поэтому страница его не выдаёт.
- Список ключей — только то, что добавили здесь. Чужие ключи на панели страница не показывает и оптом не удаляет.
- Телефонный NFC не заменяет Mifare-ключ.
- Страница — сборка Vue в `web/dist`. После правки `web/` её нужно собрать заново: `npm run build` в каталоге `web/`, либо пересобрать образ. Вкладку после этого обновляют.
